## 什么是 Claude Code

Claude Code 是 Anthropic 推出的**终端原生 AI 编程助手**。它不是一个 IDE 插件，而是一个可以直接在命令行里工作的 AI Agent。

和 Copilot 的"自动补全"、Cursor 的"Tab 补全 + 对话编辑"不同，Claude Code 的设计哲学是**理解 → 规划 → 执行 → 验证**的完整闭环。你把需求给它，它会自己读代码、改文件、跑命令、修 bug，直到任务完成。

## 三种工具的本质差异

先理清定位：

| | Claude Code | Cursor | GitHub Copilot |
|---|---|---|---|
| **形态** | 终端 CLI | AI 原生 IDE | IDE 扩展 |
| **核心优势** | 深度推理 + 自主多文件重构 | 最强 Tab 补全 | 最广 IDE 兼容 |
| **工作方式** | Agent 自主闭环 | 对话 + 补全驱动 | 补全为主 |
| **上下文** | 200K tokens | 128K tokens | 128K tokens |
| **月费起步** | $20（Pro） | $20（Pro） | $10（Pro） |

一句话总结：Copilot 帮你写几行，Cursor 帮你写一个文件，Claude Code 帮你搞定整个项目。

这个差异背后是架构理念的不同。

## /goal：设定目标，让 AI 自己跑

Claude Code 有一个独特的功能叫 `/goal`——你设定一个完成条件，它会在多个回合之间持续工作，直到目标达成。

```
/goal 给博客添加标签聚合页面，每个标签一个页面
```

然后它会自己：
1. 扫描项目结构，理解现有内容
2. 规划实现方案
3. 创建文件、写代码
4. 跑构建验证
5. 循环直到完成或遇到需要你决策的问题

期间会显示实时覆盖层：已用回合数、耗时、Token 消耗。

## MCP：AI 连接外部世界

MCP（Model Context Protocol）是 Anthropic 推出的开放协议，让 AI 能连接数据库、API、文件系统等外部资源。2026 年已经有 10,000+ 公共 MCP 服务器。

对开发的直接影响：

- 连接 Notion/Linear 读取需求文档，自动生成代码
- 连接 Supabase/数据库，AI 直接查表结构再写 SQL
- 连接 Figma，从设计稿生成组件
- 连接浏览器，AI 能看实际渲染结果

MCP 解决了 AI 编程最大的痛点：AI 不知道你项目之外发生了什么。

## 实际使用体验

### 好的部分

**真正的多文件重构。** 让它"把项目里所有日期格式从 MM/DD/YYYY 改成 ISO 8601"，它能自己找到所有相关文件、逐一修改、跑测试验证。

**会自我审查。** Claude Code 有 Dreaming 机制——在子任务之间自动暂停，审查已完成的工作，确认方向正确后再继续。这不是事后检查，而是嵌入工作流里的。

**Token 效率惊人。** 实测中，同等复杂任务 Claude Code 消耗的 Token 仅为 Cursor 的 1/10 ~ 1/13。因为它先理解全貌再动手，而不是对话堆 Token。

### 不好的部分

**没有 GUI。** 改 CSS 时看不到渲染结果，只能靠代码推断。做前端页面调样式很痛苦。

**响应偏慢。** 每次开始执行前要分析上下文，等 5-10 秒才有反应。习惯 IDE 实时补全的人会不适应。

**只能用 Claude 模型。** 没得换，不能切 GPT 或 Gemini。

**终端学习曲线。** 如果平时不用命令行，上手需要时间。

## 最佳实践

### CLAUDE.md 是灵魂

`CLAUDE.md` 是给 AI 的项目说明书。好的 CLAUDE.md：

- 写项目特有的、AI 从代码里推断不出来的东西
- 写容易踩的坑和环境配置
- 不要写语言规范、代码风格之类 AI 自己知道的东西
- 判断标准：删掉这一行会不会让 AI 犯错？不会就删

### Explore → Plan → Implement → Commit

官方推荐的标准工作流：

1. **Explore**：只读模式分析代码，不做修改
2. **Plan**：写出详细实现方案，评审后再动手
3. **Implement**：按计划执行，边做边验证
4. **Commit**：写好 commit message

跳过 Plan 的唯一场景：修 typo、加一行日志、改名——改动的描述能在一句话内说完。

### 上下文管理

- **不相关任务之间 `/clear`**，防止上下文污染
- **修正超过两次还不对？** `/clear` 重新来，换个更好的 prompt
- **复杂项目配 `.claudeignore`**，排除 `node_modules/`、`dist/` 等
- **用子 Agent 做搜索**，只让摘要回到主对话，能省 40%+ tokens

### 给 AI 设定约束

模糊指令是产出差的主要原因：

| 差的指令 | 好的指令 |
|---------|---------|
| "代码写简洁一点" | "文件不超过 200 行，函数不超过 20 行" |
| "不要过度设计" | "不引入新的抽象层，不写未使用的接口" |
| "写一些测试" | "给所有导出函数写单元测试，覆盖边界情况" |

## 适合什么场景

**最适合：**
- 复杂代码库的大规模重构
- 从零搭建新项目
- 跨多个文件的 bug 修复
- 代码审查和安全审计（内置 `/review` 命令）

**不太适合：**
- 频繁的 CSS 样式微调
- 需要实时预览的前端页面调整
- 单行补全（大材小用）

## 总结

Claude Code 代表了 AI 编程工具的一个方向：**不是让你写得更快，而是让 AI 自己去写，你负责审查和决策。** 它适合愿意用终端、处理复杂任务的开发者。

对于个人项目——比如这个博客——Claude Code 从初始化到写文章到部署，几乎可以覆盖全流程。本博客的后续功能迭代也会用 Claude Code 来驱动，每次改进的过程都会记录下来。

**推荐组合：Claude Code（复杂任务）+ Copilot（日常补全），月费 $30 起，覆盖 95% 的开发需求。**
